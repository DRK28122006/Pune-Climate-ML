# Session 13 — Final ML audit and engine sign-off

**Suggested model:** Beam Free (1M context for the cross-repo audit). Ask DeepSeek V4.1 Flash to review the final diff if available.  
**Dependencies:** Sessions 9, 10, 11, and 12 merged or explicitly blocked.  
**Owns:** `ml_pipeline/research/08_signoff/ML_SIGNOFF.md` and any status-only corrections needed to make the audit honest.  
**Do not touch:** scoring logic, validation harness logic, `frontend/`, `backend/`, measured constants, PDF by hand.

Read `prompts/00_context.md` and `prompts/00_review_findings.md` first.

## Mission

Decide whether the ML pipeline is ready to hand to full-stack integration. Do not fix code in this session unless a trivial documentation/status correction is needed. The output is an evidence-backed sign-off, not optimism.

If green, drainage, or slope are still missing, sign-off is **CONDITIONAL / NOT READY**, not `PASS`.

## 1. Run the full test matrix

Use `.venv/bin/python` if it exists; otherwise use the project’s working environment.

```bash
python -m pytest -q
python -m pytest ml_pipeline/tests -q
python ml_pipeline/tests/test_scoring.py
python ml_pipeline/tests/test_narrative.py
python ml_pipeline/tests/test_data_integrity.py
python ml_pipeline/tests/test_e2e_ward12.py
python engine/tests/test_engine.py
python engine/tests/test_strict.py
python ml_pipeline/data/check_provenance.py
```

Record each result as one of:

- `PASS`
- `FAIL`
- `SKIP` with the exact missing dependency
- `BLOCKED` with the exact missing artifact

Do not treat a skip as a pass. Do not claim “all tests pass” if any test is skipped because data is missing.

## 2. Verify the partial-evidence contract

Run a small deterministic script against the current scorer and check:

| Available factors | Expected |
|---|---|
| 4/4 | `evidence_status=COMPLETE`, `decision_grade=true`, numeric composite |
| 3/4 | `evidence_status=PARTIAL`, `decision_grade=false`, `REVIEW` |
| 2/4 | `evidence_status=INSUFFICIENT`, composite/band `None`, `REVIEW` |
| 1/4 | `evidence_status=UNAVAILABLE`, composite/band `None`, `REVIEW` |
| 0/4 | `evidence_status=UNAVAILABLE`, composite/band `None`, `REVIEW` |

Also verify:

- A carbon-only BOQ does not produce a `Low` decision-grade band.
- `RecommendationEngine` does not crash with `impervious_pct=None`.
- Recommendations do not invent 60/30 land cover.
- The renderer does not print a normal score/band for a non-decision-grade result.
- The narrator prompt receives `evidence_status` and `decision_grade`.

## 3. Verify data and provenance

Check:

- `ml_pipeline/data/epoch_cube.json` has 864 cells and the current epoch.
- `tree_index.sqlite`: present/valid with `4,009,623` unique trees, or explicitly missing.
- `reference_layers.sqlite`: valid with `wards`, `parks`, `storm_drains`, or explicitly missing/0 bytes.
- `ward_validation.json` and `site_validation.json` have current provenance and match the current config/cube hashes.
- `check_provenance.py` passes.
- No current artifact contains `4,009,624`.
- No current artifact contains fabricated `mean_slope_deg: 3.0` or `slope_multiplier: 1.05` unless labelled `SYNTHETIC_FIXTURE` or `STALE`.
- No current artifact contains fake `dist_to_storm_drain_m: 150` or `200`.
- `docs/example_assessment.json` is either current or clearly synthetic/stale.
- `stress/` and `e2e/` are either current or clearly marked stale.

## 4. Verify the report and README

Check:

- `docs/Dishadharti_ML_Report.pdf` exists, has a recent timestamp, and is generated by `docs/make_report.py`.
- The PDF does not claim green validation, drainage validation, slope validation, or full e2e success that the artifacts do not support.
- README ranges match current artifacts or are labelled partial/unavailable.
- MANIFEST statuses match the files.
- No legal/policy claim is stronger than its source.
- The web demo is still labelled prototype; do not wire it in this session.

## 5. Check the engine handoff

Check:

- `engine/region.py` strict mode still rejects provisional constants.
- `engine/score.py` propagates the partial-evidence fields.
- `engine` does not silently default missing land cover, slope, or drainage.
- The any-region claim is limited to what strict mode supports.

Do not expand the any-region feature in this session.

### D. Residual limitations

List every limitation that is still true:

- Heat elevation confounding.
- Fluvial flood not modelled.
- Green unavailable if the census/tree index is missing.
- Flood slope missing if the cube has no slope band.
- Drainage missing if reference layers are absent.

### E. What full-stack may and may not claim

Be explicit. For example:

- May claim: deterministic four-factor screening when all inputs exist.
- May claim: missing factors are withheld and partial results are not approvals.
- May not claim: flood/heat accuracy, green validation without the census, floodplain exposure, or any-region portability.
- May not claim: web demo results are measured assessments.

### F. Recommendation

State the next action:

- Start full-stack integration only after the P0 items are closed; or
- Restore the missing data first; or
- Fix the remaining code defect first.
